## 2. Воронка лидов — 7 стадий канбана

URL: `/manager/leads/board`

```
┌────────┬──────────┬──────────────┬──────────────┬────────────┬────────┬───────────────┐
│ Новые  │ Связались│ КП отправлено│ Договор подп.│ Реализована│ Оплата │ Не состоялась │
└────────┴──────────┴──────────────┴──────────────┴────────────┴────────┴───────────────┘
```

### Что значит каждая колонка

| Колонка | Смысл | Что Регина уже сделала |
|---|---|---|
| **Новые** | Заявка только что упала с сайта (через n8n) или Регина создала её руками | Ничего, ждёт реакции |
| **Связались** | Регина дозвонилась/написала, обсудила потребность | Звонок + квалификация |
| **КП отправлено** | КП сгенерирован и улетел клиенту по email | Создан клиент-черновик + draft-сделка + DOCX КП в storage |
| **Договор подписан** | Клиент согласился, договор подписан со стороны клиента | Создан полноценный клиент с реквизитами + active-сделка |
| **Реализована** | Все работы по договору выполнены | Сгенерированы акты работ |
| **Оплата** | Деньги получены | Сделка закрыта (status=`completed`) |
| **Не состоялась** | Клиент отказался / не дозвонились / спам | Лид помечен с причиной потери (9 кодов) |

### Как двигается лид

**Drag-n-drop** карточки между колонками. Особые drop:

- **→ Связались / Реализована** → просто меняется статус, без модалки
- **→ КП отправлено** → открывается **«Сформировать и отправить КП»**:
  - Тип клиента (Юр / Физ)
  - Название
  - Email (предзаполнен из лида)
  - Прайс-позиции (м², способ, цена, НДС 5%)
  - Срок действия КП (по умолчанию +14 дней)
  - **На submit:** создаёт клиент-черновик + draft-сделка + DOCX КП → отправляет email клиенту → лид → `proposal_sent`
- **→ Договор подписан** → открывается **«Конвертировать в клиента»**:
  - Тип клиента, название, чекбокс «Сразу создать сделку» (default ON)
  - **На submit:** создаёт клиента + (опционально) сделку → редирект в карточку
- **→ Не состоялась** → открывается **«Причина потери»**:
  - 9 кодов: дорого / выбрали конкурента / не дозвонились / не актуально / отложили / решили сами / не наш регион / спам / другое + комментарий

При **Отмене модалки** статус лида откатывается к исходному.

## 3. Полный сценарий «новая заявка → закрытая сделка»

Дальше — пошагово, как Регина ведёт клиента от первого звонка до получения оплаты.

### Шаг 0. Заявка прилетела

Источник: форма на сайте `дезтехюг.рф` → n8n → POST `/api/leads/inbound` → новый лид со статусом `new`.

Регина открывает `/manager` и видит на дашборде «**Новые заявки: 1**» — кликает.

### Шаг 1. Взять в работу

`/manager/leads` — список или `/manager/leads/board` — канбан.

В карточке лида (`/manager/leads/[id]`):
- Кнопка **«Взять в работу»** — назначает себя ответственной (`assigned_manager_id = me`)
- В шапке dropdown статуса — переводит лид в `contacted` после звонка
- В разделе «Сырые данные» (свёрнуто) — JSON от n8n для отладки

### Шаг 2. Сформировать и отправить КП

**Способ A — через канбан (быстрый):**
1. На канбане перетащить карточку из «Связались» в «КП отправлено»
2. Заполнить ProposalDialog:
   - Юр/Физ
   - Название организации
   - Email (предзаполнен)
   - Добавить позиции прайса: «Дезинсекция кухни 180 м² · Туман · Ежемесячно · 8 500 ₽»
   - Срок действия КП
3. Нажать **«Сгенерировать и отправить»**

Что происходит за один клик:
- ✅ Создан минимальный клиент (только название + email + телефон, без реквизитов)
- ✅ Создана draft-сделка с привязкой к лиду
- ✅ Записаны прайс-позиции с автосчётом НДС 5%
- ✅ Сгенерирован DOCX КП с номером `КП-2026-NNN`
- ✅ Отправлен email клиенту с сопроводительным текстом + DOCX во вложении
- ✅ Лид → `proposal_sent`, привязан к клиенту и сделке
- ✅ Регина оказывается на табе «Документы» новой сделки

**Способ B — из карточки клиента (если клиент уже создан):**
1. Открыть `/manager/clients/[id]`
2. Кнопка **«Создать сделку»** в шапке
3. В табе «Прайс» — добавить позиции
4. В табе «Документы» — кнопка «Сгенерировать → Коммерческое предложение»
5. Нажать «Отправить клиенту» в строке КП

### Шаг 3. Клиент согласился — заключаем договор

После звонка клиента «согласны на ваши условия»:

1. Зайти в карточку сделки `/manager/deals/[id]`
2. **Tab «Реквизиты»** — inline-edit:
   - Если клиент юрлицо — заполнить ИНН, КПП, ОГРН, банк, директора (валидируется по ФНС/ЦБ)
   - Установить даты start_date / end_date
3. **Tab «Документы»** — кнопка «Сгенерировать → Договор»
4. Скачать DOCX → распечатать в 2-х экз → подписать Региной + ИП Белавиной
5. Отправить клиенту по email или передать лично
6. Когда вернётся подписанный — кнопка «📎 Загрузить скан» в строке документа
7. Сменить статус сделки **«Подписан»** через dropdown в шапке

На канбане лидов лид автоматически едет в **«Договор подписан»**.

### Шаг 4. Назначить мастера на выезд

В табе **«Реквизиты»** сделки:
- Поле «Исполнитель» — dropdown активных мастеров
- Выбрать Александра → сохранить

После этого Александр в своей CRM (`/master`) видит сделку в списке.

### Шаг 5. Мастер делает работы

Александр заходит на `/master` — видит **только свои сделки** (где он `assigned_master_id`), сгруппированные по статусу.

Открывает карточку `/master/deals/[id]`:
- **БЕЗ цен и сумм** (видит только что делать, где, кому позвонить)
- Контакт клиента: имя + телефон + email
- Объекты: адрес (link на Я.Карты), площадь, контакт на месте
- План работ (прайс-позиции, но без цен — только название, м², метод, частота)
- Журнал ранее выполненных работ

После выезда:
- Кнопка **«Записать работы»** → форма (date, описание, area_m2, заметки)
- Запись падает в `deal_work_logs`
- Когда все работы по плану выполнены — кнопка **«Завершить выезд»** → сделка → `completed`

### Шаг 6. Регина оформляет акт и счёт

После завершения цикла работ:

1. В карточке сделки `/manager/deals/[id]` → tab «Документы»
2. **«Сгенерировать → Акт работ»** — DOCX автоматически собирается из `deal_work_logs` за выбранный период
3. **«Сгенерировать → Счёт»** — стандартный счёт по реквизитам ИП Белавиной + сумме сделки
4. **«Отправить клиенту»** — email с обоими документами

При получении подписанных актов:
- Загрузить сканы в строки документов
- Сменить статус документов на «Подписан»
- Сменить статус сделки на «Завершена» (`completed`)

### Шаг 7. Получение оплаты

После прихода денег:
- На канбане перетащить лид в **«Оплата»** (won)
- Сделка остаётся в `completed`, но в дашборде KPI «Реализованы за 30 дней» прибавляется

## 4. Доп. соглашения (ДС) — изменения по ходу

Если клиент подключает новый объект или меняет тариф:

1. В карточке сделки → tab **«ДС»**
2. Кнопка **«Создать ДС»** → форма (номер, дата, описание изменений, JSON-структура)
3. На вкладке появляется ДС с внутренним номером (1, 2, 3 в рамках сделки)
4. Кнопка **«Сгенерировать DOCX»** → создаст ДС с **сквозным официальным номером** `ДС-2026-NNN` (один счётчик на год для всех сделок)
5. Отправить клиенту → загрузить подписанный скан

## 5. Документооборот — все 6 типов

| Тип | Префикс | Когда генерируем |
|---|---|---|
| **Договор** (`contract`) | ДГ-2026-NNN | Один раз при подписании |
| **Доп. соглашение** (`addendum`) | ДС-2026-NNN | По мере изменений |
| **Акт работ** (`act_work`) | АР-2026-NNN | После каждого выезда / по итогам месяца |
| **Акт обследования** (`act_inspection`) | АО-2026-NNN | Перед стартом договора (по необходимости) |
| **Коммерческое предложение** (`commercial_offer`) | КП-2026-NNN | На стадии «КП отправлено» |
| **Счёт на оплату** (`invoice`) | СЧ-2026-NNN | После выполнения работ |

**Нумерация сквозная по году+типу.** То есть `ДГ-2026-101` — это 101-й договор за 2026 год у всех клиентов вместе.

### Что можно сделать с документом (в табе «Документы»)
- ⬇️ **Скачать DOCX** / PDF
- ✉️ **Отправить клиенту** — email с шаблонным сопроводительным текстом + вложение
- 🔄 **Перегенерировать** — создаст новую версию (старую → archived)
- 📎 **Загрузить подписанный скан**
- 🗑️ **Удалить** — снесёт DOCX/PDF/scan из storage и запись из БД

### Шаблоны DOCX

Базовые 6 шаблонов уже зашиты. Если заказчику нужна другая форма:
1. Саня заходит в `/admin/templates`
2. В нужном типе нажимает **«Загрузить версию»**
3. Drag-n-drop своего DOCX (с правильными переменными `{{client.shortName}}`, `{#priceItems}{customName}{/priceItems}` и т.д.)
4. Файл валидируется через docxtemplater (битые отклоняются с понятной ошибкой)
5. Старая версия → `isActive=false`, новая → активная

После этого все новые сгенерированные документы этого типа берут твой шаблон. Старые остаются на той версии, которой были созданы (можно посмотреть в БД `documents.templateId`).

## 7. Управление юзерами (admin)

URL: `/admin/users`

CRUD юзеров с генерацией одноразового пароля:

1. Кнопка **«Создать юзера»** → форма (email, ФИО, телефон, роль)
2. Система генерирует случайный пароль (12 символов, bcrypt в БД)
3. **Plaintext пароль показывается ОДИН РАЗ** в toast с кнопкой «Копировать»
4. Передать новому юзеру (СМС/мессенджер)
5. При первом входе CRM принудительно потребует сменить пароль

Можно:
- Сменить роль
- Деактивировать (юзер не сможет войти)
- Сбросить пароль (выдаст новый одноразовый)

Защита: ты не можешь деактивировать или поменять роль самому себе.
