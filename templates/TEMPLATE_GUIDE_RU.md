# 📄 Инструкция: как подготовить шаблоны документов в CRM ДезТехЮг

> Полный цикл + расшифровка всех плейсхолдеров. Для Сани и Регины.
> Актуально на 2026-06-08 (Sprint 10 — единицы измерения у услуг объекта; сверено
> после заказ-нарядов Релиз A/B — плейсхолдеры документов не менялись).

---

## 0. Коротко (TL;DR)

1. Берёшь Word-файл (`.docx`) с нужной вёрсткой, лого, печатями.
2. В местах, где должны подставляться данные, пишешь **плейсхолдеры** — слова в фигурных скобках: `{client.shortName}`, `{contract.number}` и т.д.
3. Заходишь в CRM → **Шаблоны** (`/admin/templates`), выбираешь тип документа, грузишь файл.
4. Жмёшь **Активировать** — теперь CRM генерит документы по этому шаблону.
5. Проверяешь: создаёшь документ в сделке/объекте и смотришь результат.

**3 главных правила, без которых ничего не заработает** — в разделе 3. Прочитай обязательно.

---

## 1. Как это вообще работает

CRM не «рисует» документы с нуля — она берёт твой `.docx`-шаблон и **подставляет данные** вместо плейсхолдеров. Технология — [docxtemplater](https://docxtemplater.com/).

```
   Твой шаблон.docx          Данные из CRM              Готовый документ
 ┌──────────────────┐      (клиент, сделка,          ┌──────────────────┐
 │ Заказчик:        │       объект, услуги)          │ Заказчик:        │
 │ {client.shortName}│  ──────────────────────►      │ ООО «Аппетит»    │
 │ ИНН: {client.inn} │                                │ ИНН: 2320155529  │
 └──────────────────┘                                └──────────────────┘
```

- На каждый **тип документа** (договор, счёт, акт…) — свой активный шаблон.
- Шаблонов одного типа может быть несколько версий, но **активна всегда одна**.
- Если активного загруженного нет — CRM берёт **базовый** шаблон из кода (они уже заведены).

## 2. Полный цикл — пошагово

### Шаг 1. Подготовить `.docx`
- Открой эталонный документ в Word (или создай новый).
- Сделай всю вёрстку как надо: шапку, лого, реквизиты, таблицы, подписи, печати.
- Там, где значение должно подставляться из CRM, **впиши плейсхолдер** (см. раздел 4).

### Шаг 2. Расставить плейсхолдеры
- Используй **одинарные** фигурные скобки: `{client.shortName}`.
- ⚠️ Печатай тег **за один заход, не исправляя по буквам** (почему — раздел 3).
- Для таблиц, где строк заранее не знаешь (услуги, позиции прайса) — используй **циклы** `{#список}…{/список}` (раздел 4.3).

### Шаг 3. Загрузить в CRM
1. Зайди в CRM под админом или менеджером (Регина может сама).
2. Меню слева → **Шаблоны** (`/admin/templates`).
3. Выбери **тип документа** (Договор / Счёт / Акт обследования / …).
4. Впиши **название** (любое понятное, напр. «Акт обследования 2026 с лого»).
5. Прикрепи `.docx` и нажми загрузить.
6. CRM сразу **проверит** шаблон: мысленно подставит тестовые данные. Если в тегах ошибка (например, незакрытый цикл) — загрузка отклонится с описанием ошибки. Это нормально, поправь и грузи снова.

> Ограничения загрузки: только `.docx`, размер ≤ 10 МБ.

### Шаг 4. Активировать
- После загрузки новый шаблон становится активным автоматически (предыдущий — в архив, не удаляется).
- Если надо вернуть старую версию — нажми **Активировать** на нужной строке. Переключение мгновенное и обратимое.

### Шаг 5. Проверить результат
- **Договор / ДС / Счёт / УПД / КП** — генерируются из карточки **сделки** (таб «Документы»).
- **Акт обследования (АО) / Акт выполненных работ (АВР)** — из карточки **объекта** (кнопки «Сформировать АО / АВР»). Объект должен быть привязан к договору.
- Открой готовый файл и проверь, что всё подставилось. Пусто в каком-то месте? → значит данные в CRM не заполнены, либо тег написан с ошибкой (раздел 6).

## 3. ⚠️ Три главных правила (грабли)

### Правило 1. Тег нужно печатать ОДНИМ махом
Word внутри разбивает текст на куски («runs») при любой правке — и если ты печатал тег по буквам / исправлял середину, он может сохраниться как `{client.` + `shortName}` в разных кусках. **docxtemplater такой тег НЕ увидит → в документе будет пусто.**

✅ Правильно: напиши тег целиком в Блокноте и вставь, **или** удали тег полностью и набери заново одним заходом.
❌ Неправильно: набрать `{clientshortName}`, потом курсором вписать точку в середину.

> Это самая частая причина «почему не подставилось». Если поле пустое, а данные в CRM есть — почти всегда дело в этом. Удали тег и набери заново.

### Правило 2. Только одинарные скобки `{ }`
`{client.inn}` — да. `{{client.inn}}` — нет (это другой синтаксис, не сработает).

### Правило 3. Циклы открываются и закрываются
Таблица с переменным числом строк (услуги, позиции) делается так: в **первой ячейке строки-образца** ставишь `{#objectServices}`, в **последней ячейке** — `{/objectServices}`. CRH размножит строку по количеству элементов. Не закрыл цикл → ошибка при загрузке.

**Бонус:** пустой тег не ломает документ. Если данных нет — на их месте просто пусто (а не слово «undefined» и не ошибка). Так что лишние теги не страшны, но и мусорить не стоит.

| `{addendum.date}` | Дата ДС |
| `{addendum.place}` | Место |
| `{contract.number}`, `{contract.date}` | Реквизиты исходного договора |

#### 🧾 Счёт (`invoice`)
| Тег | Что |

Те же поля, что у счёта, но с префиксом `{upd.*}`: `{upd.number}`, `{upd.date}`, `{upd.basis}`, `{upd.totalNet}`, `{upd.vatAmount}`, `{upd.totalGross}`, `{upd.totalInWords}`.

### 4.3. Циклы (повторяющиеся строки в таблицах)

Цикл = строка таблицы, которая размножится по числу элементов. `{#имя}` в первой ячейке строки, `{/имя}` в последней.

#### `{#objectServices}` — услуги объекта (для АО / АВР) ⭐ НОВОЕ (Sprint 10)
Заполняется, **когда акт формируется по объекту** (кнопка в карточке объекта). Каждая услуга объекта = отдельная строка.

| Тег внутри цикла | Что |
|---|---|
| `{index}` | № строки (1, 2, 3…) |
| `{objectName}` | Название объекта |
| `{objectAddress}` | Адрес объекта |
| `{serviceName}` | Название услуги (Дезинсекция, Фумигация…) |
| `{method}` | Способ обработки |
| `{areaLabel}` | **Готовая строка с единицей: «500 м²» / «7,7 м³» / «5 ед.»** ← удобнее всего |
| `{quantity}` | Только число (500 / 7,7 / 5) |
| `{unit}` | Код единицы (m2 / pcs / m3) |
| `{unitLabel}` | Только единица (м² / ед. / м³) |

**Пример строки таблицы в Word** (5 колонок):
```
┌─────┬──────────────┬────────────┬─────────────┬──────────────┐
│  №  │   Объект     │   Адрес    │  Площадь    │   Услуга     │
├─────┼──────────────┼────────────┼─────────────┼──────────────┤
│{#objectServices}{index}│{objectName}│{objectAddress}│{areaLabel}│{serviceName}{/objectServices}│
└─────┴──────────────┴────────────┴─────────────┴──────────────┘
```
(`{#objectServices}` приклеивается перед `{index}` в первой ячейке, `{/objectServices}` — после `{serviceName}` в последней.)

> Альтернатива одной строкой (если не нужна таблица): тег `{services}` выведет все услуги перечнем — «Дезинсекция — 500 м²; Фумигация — 7,7 м³».

#### `{#priceItems}` — позиции прайса (для договора / ДС / счёта / УПД / КП)
| Тег внутри цикла | Что |
|---|---|
| `{index}` | № позиции |
| `{serviceName}` | Услуга |
| `{objectName}` / `{objectAddress}` | Объект и адрес позиции |
| `{area}` | Количество (число) |
| `{areaUnitLabel}` | Единица (м² / ед. / м³) |
| `{method}` | Метод обработки |
| `{frequency}` | Кратность (Ежемесячно / По заявке) |
| `{priceNet}` | Цена без НДС |
| `{priceGross}` | Стоимость с НДС |
| `{vatRate}` | Ставка НДС (5) |
| `{quantity}` / `{unit}` / `{amount}` | Кол-во / ед. / сумма (для счёта) |

#### `{#workLogs}` — журнал выездов (для АВР)
| Тег | Что |
|---|---|
| `{index}` | № |
| `{date}` | Дата выезда |
| `{description}` | Что сделано |
| `{area}` | Площадь |
| `{master}` | Мастер |
| `{notes}` | Примечания |

#### `{#objects}` — объекты клиента (старый формат, для актов)
`{index}`, `{name}`, `{address}`, `{area}`, `{service}`. Менее удобен, чем `{#objectServices}` — рекомендуем новый.

## 5. Шпаргалка: какой документ откуда генерится и какие одиночные данные доступны

| Документ | Откуда генерить | Объектные данные (`{object.*}`, `{contact.*}`, `{master.fio}`, `{services}`, `{#objectServices}`) |
|---|---|---|
| Договор, ДС, Счёт, УПД, КП | Карточка **сделки** → таб «Документы» | ❌ не заполняются (документ по всей сделке, не по одному объекту) |
| **АО, АВР** | Карточка **объекта** → «Сформировать АО/АВР» | ✅ заполняются (документ по конкретному объекту) |

Одиночные «объектные» теги (есть в АО/АВР по объекту):
`{object.name}`, `{object.address}`, `{object.area}`, `{contact.fio}`, `{contact.phone}`, `{master.fio}`, `{document.number}`, `{document.date}`, `{deal.contractNumber}`, `{deal.contractDateLong}`.

## 6. Частые проблемы

| Симптом | Причина | Решение |
|---|---|---|
| Поле пустое, хотя данные в CRM есть | Тег «расплылся» по кускам в Word (Правило 1) | Удали тег целиком и набери заново одним заходом |
| Загрузка отклонена «не прошёл валидацию» | Незакрытый цикл (`{#x}` без `{/x}`) или опечатка | Проверь пары `{#…}`/`{/…}`, исправь, грузи снова |
| Таблица услуг пустая в АО/АВР | Генерил из сделки, а не из объекта; или у объекта нет услуг | Генерь из карточки объекта; добавь услуги объекту (с кол-вом и единицей) |
| Вместо значения слово целиком осталось `{client.inn}` | Двойные скобки или кривой тег | Только одинарные `{ }`, проверь написание |
| Единица не та (м² вместо м³) | У услуги объекта выбрана не та единица | Карточка объекта → услуга → поле «Ед.» |

## 7. Для разработчика (техническая часть)

- Базовые шаблоны собираются скриптом `python3 tools/build-templates.py` → кладутся в `templates/*.docx`.
- Источник данных: `lib/templates/build-data.ts` (там формируется объект `data` по типу документа).
- Рендер: `lib/render-docx.ts` (docxtemplater + dot-notation parser; пропущенный тег → пустая строка).
- Реквизиты исполнителя: `lib/contract-provider.ts`.
- Загрузка/активация/валидация: `app/(crm)/admin/templates/actions.ts`.
- Активный шаблон выбирается так: запись в БД `document_templates` с `is_active=true` (последняя версия). Если такой нет — fallback на файл из `templates/` по типу.
- ⚠️ Если добавляешь НОВЫЙ плейсхолдер в шаблон, которого ещё нет в `makeTestData()` (в `actions.ts`) — валидация всё равно пройдёт (parser возвращает пусто), но для корректной проверки тестовые данные стоит дополнить.
